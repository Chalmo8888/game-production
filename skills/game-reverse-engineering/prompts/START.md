# 从游戏链接开始：研究并交付 Creator Base

适用场景：新设备、新 Agent、空文件夹都可以。最少只需要提供一个网页游戏链接；交付目标可以不写，默认是 Creator Ready Base。替换【】中的内容后整段发送：

```text
请使用 Game Reverse Engineering Skill，研究下面的参考游戏，尽可能自动还原它成熟的玩法与制作能力，
最终交付一个能够快速替换美术、修改玩法、批量生产原创游戏的 Creator Base。

参考游戏（网页游戏链接；也可以是开源仓库或本地工程路径）：
【粘贴链接】

Skill 仓库：
https://github.com/Chalmo8888/game-production
（使用仓库中的 skills/game-reverse-engineering 目录；具体游戏的制作由同仓库的 skills/game-creation-polish 负责，本次不做）

补充目标（可选）：
【例如：H5 横版射击；保留或提升原版的手感、敌人与 Boss、武器、关卡事件、拆件动画、特效、UI 和资源管线。
留空表示交付 Creator Ready Base，不需要正式游戏和商业级美术。】

获取并加载 Skill：如果当前项目已有 .agents/skills/game-reverse-engineering/，以它为准；否则把上面的
仓库克隆或下载到项目之外的临时目录，阅读 skills/game-reverse-engineering/SKILL.md，然后运行
python <临时目录>/skills/game-reverse-engineering/scripts/gre.py init --project <当前目录>
--code-path <Base 代码目录> --core-path <引擎核心目录> --starter-path <示例内容目录> --reference <参考链接> --basis "<我的原话>"
它会把 Skill 固定安装到当前项目并创建工作区记录，不覆盖已有文件。已有工程按 prompts/TAKEOVER.md 接管；
之后每次开始先运行 gre.py resume。

按 SKILL.md 的 E0–E7 推进，由你一个 Agent 完成全部工作：
E0 技术调查（包括能否动态运行原作）并当天建立 Base 骨架 → E1 授权与复用判断 → E2 源码与动态行为研究 →
E3 能力等价矩阵覆盖 15 个能力域，并发现模板之外的游戏特有能力 → E4 逻辑系统 →
E5 表现系统重建：原版管线优先——先盘点参考资料（原版能否运行、有无合法原版像素、有哪些场景类型），
研究原版怎样把背景、地图几何、角色、动画、阴影、遮挡、特效和 UI 组合成画面，每个场景类型做帧研究，
每个调查项写 A/B/C/D 判定，方法不同就写差异、原因和影响 → E6 两套原创 Creator 测试配置，
然后通过解耦、创作者工具包和干净首次使用门禁（CREATOR_CANDIDATE），并争取独立 Agent 复用验收（CREATOR_READY）→
E7 报告、冻结版本、gre.py export 导出创作交接。

规则：能合法复用的成熟代码和系统优先复用；不能合法复用的按原版方法独立重建；难以恢复的细节评估改用
授权明确的成熟组件。原版来自可下载游戏、公开仓库或反编译工程，都不代表可以商业使用；没有权利的代码和
资源只放在被忽略的 research-private/。只有带运行时或测量证据、绑定当前代码的 VERIFIED 才算完成。
没有证据证明原版这样做，就不能写“与原版相同”；占位图和自有美术的截图只证明 Base 自洽，不能当作原版证据；
没有合法原版像素时，视觉保真度保持 NOT VERIFIED。核心不得依赖或写死示例内容。研究结论更正后，
用 --correct --affects 记录并重新验证下游实现。无法组织独立 Agent 验收时如实停在 CREATOR_CANDIDATE。
每轮用 gre.py next 选择价值最高的缺口。权利记录（RE01/RE03/RE02）与技术等级分开，不宣称零版权风险。

【无人值守执行规则】
开始调查并执行，直到达到当前授权范围内可验证的交付目标，或遇到无法自行解决的真实外部阻断。
只要执行环境允许、授权与预算范围内仍有有价值且可执行的工作，就继续研究、设计、实现、测试、
检查、返工和扩展。不要因为完成一个小版本、研究文档或演示程序就主动停止。优先解决对 Base 能力
和可复用性影响最大的缺口。如果工具挂起，及时检测并恢复。如果某项工作受阻，记录原因并继续其他
可执行任务。同一方案连续失败，应重新调查根因，不无意义重试。测试结果必须保留历史证据，不得直接
覆盖重要记录。不要通过空转、重复小修和无效提交制造工作时长。执行环境中断时，保存精确状态与
恢复入口，不假装仍在后台运行。停止时用 gre.py stop 记录真实状态。

本次只交付研究和 Base，不制作游戏。在稳定检查点创建本地 Git commit。未经明确授权，不 push、
不公开部署、不付费、不上传研究原件或原作资源、不删除无关文件。

最终报告：Base 位置与版本、证据支持的交付等级、机制保真度与视觉保真度（分开）、A/B/C/D 判定统计与主要差异、
能力等价矩阵报告路径、游戏特有能力、复用与隔离情况、两套测试配置、创作者工具包与首次使用结果、
独立复用状态、创作交接文件路径、权利状态、未完成项和下一步。现在开始实际工作，不要只回复计划。
```
