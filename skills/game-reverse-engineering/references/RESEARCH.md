# 逆向研究规范（E0、E2）

## 1. 研究为建设服务
- 每个研究任务都要指向 PARITY 中的一个条目（`task start --kind research --item <id>`），写明要回答的问题、时间盒和退出条件。
- 退出条件三选一：(a) 拿到足以实现的证据；(b) 证明无法获得，把条目降为 STATIC_ONLY/INFERRED/PROXY 并写 dynamic_gap；(c) 判定与 Base 目标无关，记为 N/A 并写依据。
- 不追求“完全逆向”。与目标无关的联机、平台或防作弊逻辑不研究。连续研究而矩阵没有进展时，工具会给出 RESEARCH_SPIN 警告，此时应立即转向建设。

## 2. E0 技术调查（第 0 天完成）
填写 `re/TECH_SURVEY.md`：
1. 获取方式与来源 URL、版本或哈希（未记录来源本身就是风险）。
2. 技术栈与可提取内容：脚本、数据表、关卡、动画格式、资源包。
3. **能否动态运行原作**：播放器或模拟器、录屏、逐帧、日志、输入回放。这一项决定后续能拿到多高的证据等级。
4. 已有的开源实现或移植及其许可证；它们往往是复用的最佳来源。
5. 权利初查与研究边界。
6. Base 骨架：代码目录、`core_paths`（只含引擎核心，不含示例内容）、测试命令、第一个可运行示例。

## 3. 分层静态提取（按需）
1. 容器与资源统计：文件类型、tag/段、资源数量。
2. 结构索引：函数或类头、调用边、回调、数据表位置，生成只含位置、哈希和关系的索引（不复制源码正文）。
3. 多视图交叉校验：例如反编译源码视图与字节码或 P-code 视图对照，避免单一工具误读。
4. 语义分类：按 PARITY 能力域标注，未分类的数量要作为可见的缺口。
5. 规则抽取：把规则写成“输入 → 处理 → 输出 + 数值单位”，并链接到条目的 `original.refs`。

研究原件（反编译输出、原始资源、内存转储）放在被忽略的 `research-private/`。引用时用 `--ref-local`，在共享记录中只保存位置和哈希。

## 4. 证据等级（原版事实可信度）
| 等级 | 含义 | 下游用法 |
|---|---|---|
| VERIFIED | 有动态证据（运行时录制、trace、测量、对比）确认 | 可以直接作为等价目标 |
| STATIC_ONLY | 只有静态代码或数据证据 | 可以实现，但必须写 dynamic_gap，并在报告中列出 |
| INFERRED | 由间接证据推断 | 同上，在 differences 中说明不确定性 |
| PROXY | 用替代行为近似 | 同上，并列出消除计划 |
| UNKNOWN | 不知道 | 不得进入实现，除非标为 IMPROVE 并写独立设计说明 |

事实可信度（原版证据等级）和 Base 能力状态（status）是两件事：原版行为已经 VERIFIED 不代表 Base 已经完成，Base 已经 VERIFIED 也不代表与原版一致。

## 5. 完整能力提取（E3）
15 个能力域都要建立条目（模板已预置 38 个通用条目，可以按项目增加）。特别检查以下容易遗漏的表现能力：
- 部件或骨骼动画与混合过渡、挂点树
- 排序键与遮挡、阴影层、混合模式
- 粒子参数与数量预算
- 九宫格 UI、位图字体
- 音效变体与去抖、对象池和缓存

这些在《植物大战僵尸》项目中都曾被遗漏。

## 6. 研究产物
- `re/TECH_SURVEY.md`、`re/DYNAMIC_STUDY.md`、PARITY 中的 `original` 字段、`.production/research/<id>/MECHANICS_MATRIX.md`（v4 兼容）。
- 每个结论可以有一份小的证据卡（例如“敌弹存活窗口 0<x<590”），带来源位置和哈希。
- 文档中引用的规格文件必须存在。
