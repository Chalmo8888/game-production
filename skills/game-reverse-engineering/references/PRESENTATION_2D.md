# 2D 表现能力重建规范（E5，PRESENTATION_READY）

表现能力和逻辑能力同等重要。只迁移玩法逻辑、表现只做到“资源能被引擎接受”，正是《植物大战僵尸》项目中出现的缺口。

## 1. 最少能力清单（对应 P1–P8）
| 域 | 能力 | 验证方式（必须有运行时或测量证据） |
|---|---|---|
| P1 | 图集打包、帧元数据（尺寸、裁切、锚点）、缩放、朝向、像素对齐 | 加载真实图集的截图；帧边界与锚点测量 |
| P2 | 逐帧（循环/一次性/速率/反向）、**拆件/部件树与挂点**、骨骼或轨道插值与混合过渡 | 连续帧序列；部件挂点随帧位置测量；混合过渡录制 |
| P3 | 动画状态机（站立、跑、跳、落地、攻击、受击、死亡）与优先级；帧事件（命中、发射、脚步）与逻辑时序对齐 | 状态切换录制；事件帧与逻辑 tick 对照表 |
| P4 | 数据化图层与视差、遮挡与排序键（行/深度/偏移）、批处理、混合模式（加法、受击闪白）、相机 | 重叠场景截图；排序断言；批次数统计 |
| P5 | 参数化粒子发射器与数量预算、事件驱动特效（命中、爆炸、拖尾）、接触阴影、透明混合、基础光照 | 录制；粒子数量与生命周期测量；阴影贴地测量 |
| P6 | 资源清单 schema、异步加载、替换与分层覆盖、占位回退的显式诊断、导入校验 | 替换前后截图；缺失资源时的诊断输出 |
| P7 | 音频清单、总线与音量组、音效与帧事件同步、变体与去抖 | 波形与帧事件对齐测量；并发上限测试 |
| P8 | 帧时间预算、高负载场景、对象池与缓存、内存上限 | 基准测试记录（目标设备、场景、样本数） |

UI 组件（九宫格、位图字体、HUD 安全区）属于 L6/P4/P6 的交叉部分，至少要在一个条目中验证。

## 2. 测量式视觉 QA
能测的就写成带阈值的断言，并接入测试，不要只停留在打印报告：
- 脚点或接地漂移（逐帧最低不透明像素与地面线之差）。
- 挂点（枪口、手）随帧位置与资产元数据一致。
- 显示轮廓与碰撞盒的偏差。
- 排序：重叠对象的绘制顺序符合排序键。
- 帧时间：在目标设备的高负载场景中统计平均值和 P95。
- UI：关键按钮命中区不被遮挡，安全区内可见。

阈值由项目的世界比例和目标设备决定（文中的 2px、32ms 只是示例）。测量脚本的输出作为 `measurement` 证据保存。

## 3. 至少一个真实资产在运行
每个表现条目的 VERIFIED 都需要运行时录制或测量证据（工具强制要求）。这意味着 Base 必须有可加载的测试资产（原创或许可清楚的资产，不用原作素材），并且真正走完“加载 → 播放 → 渲染”的完整路径，不能只有单元测试，也不能用空的资产清单（例如 `units: {}`）。

## 4. 降级与差异
- 离线烘焙（把分层动画烘焙成逐帧）、调试图形、整体形变代替部件动画等方案都是降级，必须写进 differences，不能当作等价实现。
- 渲染方案可以与原版不同（例如 WebGL 合批代替软件渲染），只要能力等价或更好，并在 differences 中写明。
- 用映射层隔离渲染方案：旧接口（帧名）映射到新实现（姿势或部件），逻辑状态机不改（《勇者之路》提交 `26b7c1e` 的做法）。

## 5. 达到 PRESENTATION_READY
在 LOGIC_READY 的基础上，P1–P8 的全部条目满足要求，每个域至少一个 VERIFIED（不能整体 N/A），P2 至少有一种动画技术完成验证。PRESENTATION_READY 仍不代表 Creator Ready：还需要证明换内容时不用改核心。
