# 无人值守与恢复规则

## 1. 核心指令
> 开始调查并执行，直到达到当前授权范围内可验证的交付目标，或遇到无法自行解决的真实外部阻断。
>
> 只要执行环境允许、授权与预算范围内仍有有价值且可执行的工作，就继续研究、设计、实现、测试、检查、返工和扩展。
>
> 不要因为完成一个小版本、研究文档或演示程序就主动停止。
>
> 优先解决对 Base 能力和可复用性影响最大的缺口。
>
> 如果工具挂起，及时检测并恢复。
>
> 如果某项工作受阻，记录原因并继续其他可执行任务。
>
> 同一方案连续失败，应重新调查根因，不无意义重试。
>
> 测试结果必须保留历史证据，不得直接覆盖重要记录。
>
> 不要通过空转、重复小修和无效提交制造工作时长。
>
> 执行环境中断时，保存精确状态与恢复入口，不假装仍在后台运行。

## 2. 授权范围
默认范围是“研究 + Base”，交付目标是 RE_STATE 中的 `target_level`（默认 CREATOR_READY），工作区的 `game_quota = 0`。达到目标就交付并停止，不自动创建游戏，也不无限扩展原作细节。用户只要求 LOGIC_READY 时，用 `init --target LOGIC_READY`。

## 3. 每轮循环
`gre.py status` 查看最大缺口 → `task start`（研究任务必须带 `--item`，并设置超时）→ 实现或研究 → 测试与测量 → `parity set` 写入证据 → `task done` → 必要时 `checkpoint` → 下一项。

优先级：
1. 阻断等级提升的核心缺口；
2. 影响多个能力域的基础设施（资产管线、状态机、事件总线）；
3. 可复用性（扩展接口、Creator 测试配置）；
4. 原作细节保真。

## 4. 工具提供的防护
| 防护 | 触发条件 | 应对 |
|---|---|---|
| STALLED | ACTIVE 任务超过 `timeout_min` | 检查进程是否挂起（例如搜索命令卡住数小时），只结束本任务启动的进程，缩小步骤后重启 |
| REPEATED_FAILURE | 同一任务失败次数达到 `same_failure_limit`（默认 3） | 停止重试，查看第一个错误，隔离最小复现，换假设或换方案 |
| RESEARCH_SPIN | 最近 N 个（默认 6）任务都是研究，而期间没有条目达到 IMPLEMENTED/VERIFIED | 立即为最大缺口建设 Base |
| POLISH_SPIN | 最近 N 个（默认 5）任务都是 polish/docs，而目标等级未达到 | 回到 `status` 列出的第一个缺口 |
| 等级声明 | 证据不足时声明更高等级 | `level --set` 拒绝，`validate` 报错 |
| 历史保护 | 证据被改动或删除、条目历史被删、HISTORY 乱序 | `validate` 报错 |

阈值在 RE_STATE 的 `guards` 中，可以按项目调整，但要写明理由。

## 5. 长任务和工具挂起
- 预计会运行很久的命令（构建、批量导出、浏览器测试）放到后台，定期查看输出；设置超时，不要无条件等待。
- 并行的浏览器测试默认最多 2 个；端口冲突时换端口；只结束能确认由本任务启动的进程。
- 输出持续增长的长构建不要盲目 kill；完全没有输出且超过预期时，按 STALLED 处理。

## 6. 证据不覆盖
- 测试、通关、测量、截图等结果用 `gre.py evidence --file <结果>` 按时间戳存入 `re/evidence/`，不覆盖旧文件（《勇者之路》的 `playthrough.json` 被覆盖后，“15/15”已无法复核）。
- 报告每次另存一份。状态中的数字以工具输出为准，不手写。
- HISTORY.jsonl 只追加；删除或修改旧证据会被发现。

## 7. 检查点与恢复
- 在完成实质任务后、做风险改动前、会话余量不足时和交接前，运行 `gre.py checkpoint --next "<下一项具体任务和命令>"`，并创建本地 Git 提交（只包含本任务的改动）。
- 中断后（同一 Agent 的新会话、另一个 Agent 或另一台设备）：
  1. 运行 `gre.py resume`：查看检查点、未关闭任务、STALLED 警告、等级与缺口、Git 状态。
  2. 处理遗留的 ACTIVE 任务：确认进程状态后重跑，或记为 failed/blocked。
  3. 换设备时运行 `gre.py env`，重新安装依赖，跑 Base 的构建和测试。
  4. 从检查点的下一步或第一个缺口继续。
- 不声称会话结束后仍在后台工作。没有可执行任务时，如实记录阻断及解除条件。

## 8. 权限
默认允许项目内的开发、测试、本地构建和本地提交。未经授权不 push、不付费、不公开部署、不删除无关文件、不提交研究原件、不绕过登录、付费或访问限制。
