# 逻辑能力重建规范（E4，LOGIC_READY）

## 1. 结构
- **核心与内容分离**：引擎核心放在 `core_paths`，单位、武器、关卡、主题等内容放在配置和数据目录。Creator 验证要求核心指纹不随测试配置变化。
- **组件化**：玩家、敌人、Boss、武器、弹道、事件分别成为组件或系统。禁止把全部逻辑塞进一个巨型模拟文件，也禁止按关卡号或帧号写死分支（《二战前线》的 `simulation.ts` 约 210 KB，其中约 71 处按 stage/frame 写死）。
- **数据驱动**：关卡用段落或波次 DSL（例如 `{w, gap, plats, spawns, arena, …}`），新机制以加字段的方式扩展；数值表带单位。
- **纯逻辑可测**：核心逻辑不依赖渲染框架，可以在无头环境中做固定步长的确定性模拟（固定种子、固定步长）。
- **逻辑为准**：移动、冷却、伤害和碰撞以逻辑规则为准，动画和图像不得暗中改变规则。原版中动画数据确实影响玩法时（例如移动轨道），把这种耦合写成显式契约，并加入校验器。

## 2. 复用、适配、独立实现
- 优先复用 KEEP 模块，适配 ADAPT 模块；不能复用的按 PARITY 中的原版规则独立实现。
- 已有能力不足的要优化（IMPROVE），并在 differences 中说明相对原版的变化。
- 原版 UNKNOWN 的行为不实现，除非标为 IMPROVE 并给出独立设计说明。

## 3. 各能力域的最低验证
| 域 | 至少要验证的内容 |
|---|---|
| L1 玩法规则 | 胜负与结算、计分或经济、固定种子下的确定性 |
| L2 控制与物理 | 输入时序（缓冲、冷却）、跳跃或移动曲线与原版测量对照、碰撞与地形边界 |
| L3 AI | 状态机转换覆盖、目标选择、Boss 阶段与部件的独立测试 |
| L4 武器技能 | 参数表驱动、命中判定、伤害与状态结算、每种行为枚举至少一个测试 |
| L5 关卡事件 | DSL 加载、触发器与延迟事件、设计约束测试（可达性、间距、软锁） |
| L6 存档与 UI 流程 | 版本迁移、损坏回退、菜单/暂停/结算流程 |

## 4. 验收走玩家路径
- 通关验证使用正常输入（自动键鼠或手柄模拟），禁止秒杀（例如 `onHit(hp+1)`）、跳关、改血、清场或扩大平台。
- 多种子、多策略；失败的种子也要记录。
- 测试结果用 `gre.py evidence` 按时间戳保存，不覆盖旧结果。

## 5. 达到 LOGIC_READY
RE01 PASS；L1–L6 的全部条目 VERIFIED（或带依据 N/A；L3、L4 可以整体 N/A，例如解谜类游戏没有敌人）。每个其他域至少有一个 VERIFIED。运行 `gre.py level --set LOGIC_READY`，证据不足时工具会列出缺口。LOGIC_READY 不代表 Base 已经可以用来做游戏：表现能力尚未验证。
