# 美术策划规范（G2）

目的：在批量生成或制作素材之前，确定完整的视觉方向和可执行的生产管线，并用一个代表资产证明这条管线在真实引擎中走得通。

## 开始前必须读取
- Base 创作者工具包（场景几何契约、角色规范、图层规则、动画导入、UI 主题、资产校验器）和实际的加载器/注册表代码：支持的格式、图集方式、骨骼或逐帧、锚点约定、尺寸和世界比例、导入命令。
- GAME_DESIGN 第 4、8、11–13 节：世界观、玩法主体、关卡、Boss、UI。
- 本机可用的生成工具与预算（ENVIRONMENT）。不可用时先规划替代方案或交接，不伪造生成。

## 三份文档
**ART_DIRECTION.md**：风格与参考方向（只取方向，不复制具体表达）、色彩体系、视觉层级、角色比例与世界尺度、场景风格、角色与敌人的设计原则、UI 视觉规范（字体和中文覆盖、安全区、分辨率）、特效规范与粒子预算、音频风格、生产方式与工具、来源与许可要求。

**ART_ASSET_PLAN.md**：资源 ID 命名与版本规则、各类资产的技术规格（格式、尺寸、朝向、锚点、挂点、导入与校验命令）、资产总清单（用途、必需动作、优先级、预估工作量、生产方式、来源要求、状态）、代表资产的试制记录、批次计划。

**ANIMATION_SPEC.md**：技术方案（逐帧/骨骼/纸娃娃/程序动画及选择理由）、动作清单（帧数、时长、循环、关键帧事件、朝向）、与逻辑的时序同步（逻辑为准，动画不得暗中修改规则）、锚点/脚点/挂点的坐标约定和容差、验证方法。

## 不合格的写法
- 只写“高质量手绘风格”，没有色板、比例、规格和生产步骤。
- 规格要求引擎不支持的格式或动画方式。
- 资产清单没有动作和朝向，导致后期才发现缺帧。
- 没有来源和许可要求，或者计划直接使用商业游戏的素材。

## 代表资产试制（D02 的硬性条件）
选一个有代表性的角色/单位和一个场景：
需求 → 生成或制作 → 加工（切图、去背、对齐、图集）→ 导入 → 动作播放 → 实机检查（脚点、挂点、朝向、命中帧、遮挡、缩放）→ 逻辑回归（同一输入/种子下，规则结果不变）。
通过后在 `.production/ASSETS.json` 中记为 `verified`，填写 runtime_files 的路径和哈希以及证据，再按试制中得到的修正去批量扩展。

## 资产状态
`planned` → `source_generated`（原料已生成）→ `processed`（已加工）→ `integrated`（已导入并被游戏加载）→ `verified`（运行时验证通过，有证据）；被否决的记为 `rejected` 并写明原因。工具会检查：integrated/verified 必须有实际加载的文件和许可依据，verified 必须有证据。

## 出口（D02）
- 三份文档的模板标记已删除，内容可以执行。
- 至少一个代表资产已 verified。
- 美术明确不在本次范围内时，D02 和 G2 标 NOT_APPLICABLE 并写依据，同时保留资产契约，方便以后接续。
