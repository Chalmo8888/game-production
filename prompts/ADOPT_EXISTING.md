# 接管已有游戏工程，不从零重做

适用场景：已经有一款开发到一半的游戏（任意目录结构，或者 v3 Skill 项目），希望纳入 v4 流程继续完成，并考虑把它的引擎作为 Base 复用。

```text
请按照 Game Production Skill 接管当前目录中已有的游戏工程，继续完成它，不要从零重做。

Game Production Skill：
https://github.com/Chalmo8888/game-production
（若项目中已有 .agents/skills/game-production/，先读取它；版本较旧时按下文迁移。）

这款游戏的最终目标：【例如：完成全部关卡和正式美术，达到本地发行候选】
是否考虑把它的引擎作为以后多款游戏的 Base：【是 / 否 / 由你评估】

1. 核对 Git、现有的启动命令、来源记录、玩法范围、资源合同、测试和最新构建。
2. 判断记录格式：
   - 有 v3 记录（.production/PROJECT.json、STATE.json、GATES.json）：运行
     project.py migrate --project <根目录>。它会原样保留 v3 的任务和证据，把原游戏登记为遗留游戏，
     存档旧 Skill，只替换 AGENTS.md 中的旧规则块（见 references/MIGRATION_V3.md）。
   - 没有任何记录：project.py init --target game；工程不在 games/ 下时，用
     game create --path <现有目录> --adopt-existing --base <base> 登记，不移动文件。
   - 是更早的 v1/v2：先读 references/MIGRATION_V1.md 或 MIGRATION_V2.md。
3. 旧报告中的 PASS，只有在版本和证据仍然适用时才保留，其余标为待复核。
4. 引擎值得复用时：先做来源审查（B02），再 base register --code-path <引擎目录>，补齐 B01–B08。
   不为了套用新结构而移动或重写引擎。
5. 优先处理已经明确的缺口，按需进入对应阶段。不因为加入 Skill 就换引擎、重写核心、
   减少单位或关卡、重新逆向参考游戏，或批量替换已经达标的美术。

【无人值守执行规则】
开始调查并执行，直到达到当前目标可验证的交付要求，或遇到无法自行解决的真实外部阻断。
只要执行环境允许，在授权和预算范围内仍有有价值且可执行的工作，就继续研究、开发、测试、
检查、返工和扩展。普通技术决策自行处理，不需要我进行阶段审批。完成一个小功能、一个里程碑
或一个版本，不构成自动停止条件。发现质量不达标，必须自主定位问题并返工。一个任务受阻，
应继续其他不依赖该任务的工作。不允许通过空循环、重复无意义操作或虚假汇报制造工作时长。
会话或执行环境终止时保存真实检查点，不声称仍在后台执行。
无人值守意味着自主完成已授权目标，不意味着无限扩大目标。

不得把占位版或只有部分模式能启动的版本报告成商业成品。普通决定不需要我批准；远程推送、
公开发布、费用、删除无关文件和修改生产环境仍需明确授权。现在开始实际工作。
```
