# 批量生产：按约定的数量或清单连续完成多款游戏

适用场景：Base 已经就绪（或在同一次授权中建立），你明确给出要做几款、各自的主题，希望 Agent 按顺序全部做完，中途不需要逐款审批。

```text
请按照当前项目中的 Game Production Skill，基于现有 Base 连续完成以下游戏。

使用的 Base：【例如 core@1.2.0；留空表示焦点 Base 的最新冻结版本】
游戏清单（按顺序）：
1. 【game-02：主题/目标】
2. 【game-03：主题/目标】
3. 【game-04：主题/目标】
每款的交付级别：【RELEASE_CANDIDATE（默认）/ GAME_READY】

请读取 .agents/skills/game-production/SKILL.md、.production/WORKSPACE.json、.production/HANDOFF.md、
Base 的 CAPABILITIES.md 和已有游戏的 retrospective（项目中没有 Skill 时，先阅读
https://github.com/Chalmo8888/game-production 的 README.md 和 SKILL.md）。

1. 用 project.py scope --target batch --game-quota <N> --basis "<我的原话>" 记录授权范围，
   N 等于上面清单中的游戏数量。
2. 按顺序逐款执行：game create（独立的 games/<slug>/，绑定 Base 版本）→ G1 游戏策划 →
   G2 美术策划与代表资产 → G3 开发 → G4 美术音频 → G5 完整 QA 与返工 → G6 独立打包 →
   G7 复盘。上一款的经验写进复盘，供下一款参考，但每款的定位、内容、数值和美术必须真正不同。
3. 每款游戏只写自己的目录。需要新的通用机制时，判断是游戏扩展还是反哺 Core；
   改 Core 要升 Base 版本，并对所有依赖游戏做回归，不能破坏已经完成的游戏。
4. 不重复已经完成且仍有效的原版研究；只有超出 Base 能力时才按需补充。
5. 完成清单中的全部 N 款后停止，不再自动增加游戏。某一款受到外部阻断时，记录下来，
   并继续不依赖它的其他游戏。

【无人值守执行规则】
开始调查并执行，直到达到当前目标可验证的交付要求，或遇到无法自行解决的真实外部阻断。
只要执行环境允许，在授权和预算范围内仍有有价值且可执行的工作，就继续研究、开发、测试、
检查、返工和扩展。普通技术决策自行处理，不需要我进行阶段审批。完成一个小功能、一个里程碑
或一个版本，不构成自动停止条件。发现质量不达标，必须自主定位问题并返工。一个任务受阻，
应继续其他不依赖该任务的工作。不允许通过空循环、重复无意义操作或虚假汇报制造工作时长。
会话或执行环境终止时保存真实检查点，不声称仍在后台执行。
无人值守意味着自主完成已授权目标，不意味着无限扩大目标。

GAME_READY 不等于 PUBLICATION_APPROVED；Game 01 通过不代表其他游戏可以发布。所有结论绑定版本
和证据。每款游戏在稳定检查点创建本地提交。未经明确授权，不 push、不公开部署、不付费、
不删除无关文件。

最终按游戏逐款报告：目录、Base 版本、就绪度与证据、打包方式、未通过事项。现在开始实际工作。
```
