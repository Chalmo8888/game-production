# 独立审查（默认只读）：游戏 / Base / 发行

适用场景：让另一个 Agent、另一个会话或真人对某款游戏（或 Base、发行候选包）做审查，输出缺陷，而不是替开发者背书。

```text
请按照当前项目中的 Game Production Skill，对【game-id / base-id / game-id 的发行候选】做独立审查。

请读取 .agents/skills/game-production/SKILL.md 和 references/QUALITY.md、references/GENRE_CHECKS.md，
以及被审对象的记录：游戏为 games/<id>/.production/ 和 design/，Base 为 .production/bases/<id>/。
本次 mode=review：只读审查代码、构建、资源、状态和证据，默认不修改被审内容。

不要沿用开发者的成功结论。按目标运行可用的检查：
- 游戏：实际画面和连续动作序列、正常输入通关/失败/重开、单位和武器的实际差异与未使用单位、
  失败种子、地图碰撞、UI/UX 与多分辨率、音频播放、存档恢复与跨游戏隔离、性能、
  内容完整度与策划是否一致、资产来源（Q01–Q08）。核对最终构建，不只测开发环境。
- Base：扩展点能否只靠配置使用、资产接口、构建测试、示例内容、来源、依赖游戏回归（B01–B08）。
- 发行：包完整性、平台规范、权利记录、批准状态（R01–R04）。审查者不能授予 R04。

每个缺陷都输出：构建/资源身份、复现步骤、期望与实际、严重程度、证据（路径和 SHA-256）、
建议修复和对应门禁。写入审查报告（templates/REVIEW.md 格式），并把任务写回被审对象的 BACKLOG。
如实记录独立性：self_review / separate_context_same_environment / independent_reviewer。
没有独立执行者，就不能写成独立 QA。

在审查范围内持续检查，直到验收标准全部覆盖，或遇到真实的工具/外部阻断；不要为了拉长检查时间
而无意义地重跑。无法证实的记为 UNVERIFIED，已有反例的记为 FAIL，不能通过删除检查项来放行。
不要通过空循环或虚假汇报制造工作时长；会话终止时保存真实进度，不声称仍在后台执行。

只有我明确授权“审查后修复”时，才先保留原始反例，再进入实施流程，修复后重新测试并更新门禁。
否则交付审查任务包。不擅自公开发布，不改写玩法。现在开始审查。
```
