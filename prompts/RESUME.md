# 换设备 / 换软件 / 新会话接续

适用场景：在另一台电脑、另一个 Agent 软件或同一软件的新对话中，接着之前的工作继续。

```text
请按照当前项目中的 Game Production Skill 接续之前的工作。

请读取 .agents/skills/game-production/SKILL.md（不能自动发现时显式读取）、
.production/WORKSPACE.json、.production/HANDOFF.md，以及焦点 Base 和焦点游戏的记录
（.production/bases/<id>/、games/<id>/.production/ 和 design/）。只有 v3 记录
（.production/PROJECT.json）时，先按 references/MIGRATION_V3.md 运行 migrate。

1. 确认上一位写入者已经交接。检查当前仓库、分支、提交和未提交的改动；不覆盖本地改动，
   不把 JSON 当作实时的跨设备锁。
2. 运行 project.py env --device-label <本机名称>，重新探测本机的路径、缓存、端口、依赖、
   浏览器和生图/音频能力，只写本地的 ENVIRONMENT。不继续使用前一台机器的 localhost、
   绝对路径或凭据，不结束其他项目的服务。
3. 运行 project.py status 和 validate：核对 Base 版本、各游戏的绑定版本、资源合同版本、
   资产/证据哈希和缺失的文件（大资产要按 ASSETS.json 的清单补齐）。
4. 先做最小构建和冒烟测试，再恢复原来的授权范围、模式、焦点和阶段。
5. 从最高优先级且未被阻断的任务继续。不重复已经验证的研究，不重新造引擎，
   不把一款游戏的状态写进另一款。

【无人值守执行规则】
开始调查并执行，直到达到当前目标可验证的交付要求，或遇到无法自行解决的真实外部阻断。
只要执行环境允许，在授权和预算范围内仍有有价值且可执行的工作，就继续研究、开发、测试、
检查、返工和扩展。普通技术决策自行处理，不需要我进行阶段审批。完成一个小功能、一个里程碑
或一个版本，不构成自动停止条件。发现质量不达标，必须自主定位问题并返工。一个任务受阻，
应继续其他不依赖该任务的工作。不允许通过空循环、重复无意义操作或虚假汇报制造工作时长。
会话或执行环境终止时保存真实检查点，不声称仍在后台执行。
无人值守意味着自主完成已授权目标，不意味着无限扩大目标。

未经预授权，不 push、不付费、不公开部署、不删除无关文件。现在开始实际工作。
```
