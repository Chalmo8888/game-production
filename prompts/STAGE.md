# 指定阶段执行（执行者不限工具）

适用场景：本次会话只负责某几个阶段，例如“只做 G1 策划”“只做 R2 Base 资产接口”“这台机器做 G3，下一台做 G4/G5”。只负责美术时，优先使用 [ART_PRODUCTION.md](ART_PRODUCTION.md)。

```text
请按照当前项目中的 Game Production Skill，只执行指定的阶段。

对象：【Base base-id，或游戏 game-id】
允许的阶段：【例如 G1,G2；或 R1,R2】

请读取 .agents/skills/game-production/SKILL.md、references/STAGES.md 中对应阶段的说明、
.production/WORKSPACE.json、HANDOFF，以及对象的记录（Base：.production/bases/<id>/；
游戏：games/<id>/.production/ 和 design/）。

用 project.py scope --target <沿用原来的项目目标> --mode stage --allowed-stages <阶段>
--basis "<我的原话>" 记录本次范围（不修改项目的最终目标）；游戏阶段另外用
game update --assign-agent <标签> --assign-stages <阶段> 记录分工。

以现有的代码、资源、证据和契约为基线，只在分配的范围内自主实现、测试、返工，直到满足阶段出口。
发现依赖缺陷时，只做本阶段必要的局部兼容修复；跨范围的大改列入任务，不偷偷推倒核心。
完成后写精确的交接（handoff --check 通过），把运行状态设为 HANDOFF_READY，不冒充全项目完成。

【无人值守执行规则】
开始调查并执行，直到达到当前目标可验证的交付要求，或遇到无法自行解决的真实外部阻断。
只要执行环境允许，在授权和预算范围内仍有有价值且可执行的工作，就继续研究、开发、测试、
检查、返工和扩展。普通技术决策自行处理，不需要我进行阶段审批。完成一个小功能、一个里程碑
或一个版本，不构成自动停止条件。发现质量不达标，必须自主定位问题并返工。一个任务受阻，
应继续其他不依赖该任务的工作。不允许通过空循环、重复无意义操作或虚假汇报制造工作时长。
会话或执行环境终止时保存真实检查点，不声称仍在后台执行。
无人值守意味着自主完成已授权目标，不意味着无限扩大目标。

未经明确授权，不 push、不付费、不公开部署、不删除无关文件。现在开始实际工作。
```

“本会话只做 G4”描述的是阶段，不意味着某个软件天生负责美术。
