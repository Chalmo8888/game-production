# Game Production Skill

**从游戏研究到完整交付的 AI 游戏生产工作流。** 适用于独立开发者与团队，不绑定 Cursor、Codex、模型、引擎或设备。

提供目标游戏链接、已有项目或一个游戏创意，让具备开发能力的 AI Agent 按统一流程完成**调查 → 合法复用与实现 → 玩法与内容 → 资源和美术 → 实机 QA → 返工 → 可验证交付**。同一个 Agent 可以完成全程，也可以由多个 Agent 跨设备接力。

> **核心原则：结果优先，证据验收，无人值守推进。** 完成一个 Demo、版本或阶段，不代表最终任务完成；但本 Skill 也不能保证 Agent 永久在线或自动证明作品可商用。

## 🚀 最快开始：复制提示词

打开 Cursor、Codex 或任何能访问 GitHub、读取文件并执行开发工具的 Agent，**替换下面的游戏链接和目标**，整段发送即可。无需先学习所有规则。

```text
我希望你按照 Game Production Skill，独立完成这个游戏项目。

参考游戏/项目（也可以是已有代码仓库）：
【粘贴游戏页面、GitHub 仓库链接，或描述原创游戏想法】

Game Production Skill：
https://github.com/Chalmo8888/game-production

最终交付目标：
【例如：研究原版成熟玩法，尽可能保留可合法复用的成果，开发一款具有原创实现和美术、可完整游玩、可供商业发行审核的 H5 游戏】

请先获取并阅读上述 Skill 仓库的 README.md、SKILL.md 和 prompts/START.md，
按实际工程情况安装或显式加载 Skill。确认当前工作目录和已有项目状态后执行，
不得在未经检查时覆盖项目文件，也不得因为换 Agent 就从零重做。

本次使用 auto 模式。你负责整个项目的规划、研究、技术选型、开发、资产管线、
美术音频（若本项目需要）、内容完善、测试、审查、返工和本地打包。
不限定 Cursor、Codex 或任何特定软件；有能力的当前 Agent 可以完成所有阶段，
也可以按照 Skill 的交接规范移交给其他 Agent。

先检查已有代码、可用开源实现、项目文档、许可证、测试和构建成果。
优先保留有依据且可合法复用的有效成果，而不是随便看一眼原作就写一个低配 Demo，
也不是无意义地重写成熟系统。对于来源存疑的反编译代码或素材，隔离研究，
不能靠改名、翻译、换皮就认定可以商业发行。

按需研究实际游戏机制、数据、关卡、动画及资源组织，形成有证据的规格；
以最终目标为导向实现真正完整的游戏循环和有差异的内容。
资源制作必须包含导入、动画验证、实际运行检查，不能把生成图片等同于美术完成。
若我明确不需要本阶段制作美术，保留可靠的资产契约并继续完成其他范围。

每轮按照：检查差距 → 选最高价值任务 → 开发或制作 → 构建和实机测试 →
发现缺陷 → 修复与回归 → 保存进度 → 自动推进下一项。
测试通过、模式能启动、自动跳关、单张截图和某一次成功通关，
不能单独证明游戏完整、好玩、动画合格或可以商业发行。
所有质量结论必须关联当前版本和真实证据，未知就记录未验证，不得自我放行。

【无人值守执行规则】
现在开始调查并执行，直到达到最终目标可验证的交付要求，
或遇到无法自行解决的真实外部阻断。
只要执行环境允许、在授权和预算范围内、仍有有价值且可执行的工作，
就持续研究、开发、测试、检查、返工和扩展；
完成一个功能、一个版本或一个阶段后自动推进，不等待我回复“继续”。
一个任务受阻就记录并继续其他任务；同一方案连续失败三轮则重新诊断或换方案。
不要为了延长运行时间而空转、无限自调用、反复生成或重复无意义测试。
达到实际交付目标后结束，不擅自无限扩张范围。
若会话、额度或工具限制导致中断，请保存可接续的状态和实际阻断原因，
不得声称在宿主停止后仍可继续工作。

记录项目目标、任务、门禁和交接状态到 .production/。
尽量完成本地真实试玩、正常操作通关、存档恢复、资源替换、性能和发行包验证，
并在稳定检查点创建本地 Git commit。未经明确授权，不 push、公开部署、
购买付费服务、上传未授权素材或修改无关项目/生产环境。

最终给出实际可运行的交付物、运行方式、源码和资产管线、
版本与测试证据、来源记录、未通过事项及进一步发布需要的审核。
不要只返回计划或功能清单，现在开始实际工作。
```

**想要的不是完整游戏？** 只需改动提示词里的「最终交付目标」。例如可指定“只分析机制、不做美术”“只制作正式美术”“审核现有游戏”“只做一个 Creator Base”。Skill 会按目标选择阶段，不强制制作不需要的内容。

## 📦 安装到项目（推荐，可由 Agent 代做）

下载或克隆本仓库，将**整个仓库文件夹**放入目标游戏项目的 `.agents/skills/`，结构如下：

```text
my-game/
├── .agents/
│   └── skills/
│       └── game-production/
│           ├── SKILL.md
│           ├── prompts/
│           ├── references/
│           ├── templates/
│           └── scripts/
└── .production/          # 每款游戏的进度和交接记录（初始化后生成）
```

从 Skill 目录执行初始化（需要 Python 3.9+）：

```bash
python scripts/project.py init --project "<你的游戏项目路径>"
```

可选：如果 Agent 不支持自动发现 Skill，明确要求它读取 `.agents/skills/game-production/SKILL.md` 即可。**仅发送 GitHub 链接并不保证所有 Agent 自动下载或启用**；需要联网、仓库访问权限和文件/命令执行能力。初始化不会代替实际的游戏开发和测试。

## 🔁 已有游戏、换设备、指定阶段

| 你要做什么 | Agent 应阅读的入口 | 说明 |
| --- | --- | --- |
| 新游戏，整个流程无人值守 | [`prompts/START.md`](prompts/START.md) | 默认 `auto`，自动推进各阶段 |
| 接管已经开发到一半的游戏 | [`prompts/ADOPT_EXISTING.md`](prompts/ADOPT_EXISTING.md) | 先验收已有成果，不重建工程 |
| 换设备或换会话继续 | [`prompts/RESUME.md`](prompts/RESUME.md) | 先核对 Git、资产、进度、设备能力 |
| 只做美术、音频等某一阶段 | [`prompts/STAGE.md`](prompts/STAGE.md) | 阶段内持续执行，结束时交接 |
| 审核和找问题 | [`prompts/REVIEW.md`](prompts/REVIEW.md) | 默认只读，基于实际证据 |
| 暂停并交给另一个 Agent | [`prompts/HANDOFF.md`](prompts/HANDOFF.md) | 保存检查点和恢复入口 |

跨设备继续**同一款游戏**时，需要同步**游戏本身的仓库和资产**，而不只是这份 Skill。每个游戏的 `.production/` 记录目标、门禁和真实进度；本地路径、端口、缓存及密钥不应随设备照搬。详见 [`references/CROSS_DEVICE.md`](references/CROSS_DEVICE.md)。

## 🧭 工作流

| 阶段 | 目标 |
| --- | --- |
| S0 · 接管与路线 | 明确目标，审查已有成果、来源、许可和能力，决定保留/适配/替换/隔离 |
| S1 · 研究与规格（按需） | 研究原游戏、开源实现、玩法数值、资源结构并保存证据 |
| S2 · 游戏实现与内容 | 完整可玩循环、差异化单位/敌人/关卡、合理状态与存档 |
| S3 · 资产接口 | 资源 ID、动画、锚点、导入、校验和替换能力 |
| S4 · 美术音频 | 正式素材制作、接入、动作检查和实际游戏表现 |
| S5 · QA 与返工 | 真实操作、关卡、动画、性能、来源、回归，不通过就修复 |
| S6 · 交付候选 | 可复现构建、发行候选包、来源记录和交接清单 |

阶段允许交叉或跳过已验证的工作。**流程按阶段组织，不绑定特定 Agent、游戏类型、开发语言、引擎或发布平台。** 完整执行规则见 [`SKILL.md`](SKILL.md) 和 [`references/STAGES.md`](references/STAGES.md)。

## ✅ 质量、安全与限制

- **不要用测试通过冒充成品**：技术检查、正常操作通关、内容完整、美术动画、平衡和发行审查各自独立。
- **不默认拥有原游戏商业授权**：研究和复用要核查代码、素材、依赖、具体表达与许可证；商用前仍需权利审查。
- **不默认拥有无限权限**：无人值守不代表允许自动付费、公开部署或访问受限内容。
- **不保证永久后台运行**：真实运行时长、工具和上下文由当前 Agent 宿主决定。中断后依靠项目进度文件接续。
- **不是万能 QA 或法律保证**：该 Skill 规范工作和证据，不替代真人体验、法律判断或平台审核。
