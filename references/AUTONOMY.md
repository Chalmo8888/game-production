# 无人值守执行合同

## 统一原则
> 开始调查并执行，直到达到当前目标可验证的交付要求，或遇到无法自行解决的真实外部阻断。
>
> 只要执行环境允许，在授权和预算范围内仍有有价值且可执行的工作，就继续研究、开发、测试、检查、返工和扩展。
>
> 普通技术决策自行处理，不需要用户进行阶段审批。
>
> 完成一个小功能、一个里程碑或一个版本，不构成自动停止条件。
>
> 发现质量不达标，必须自主定位问题并返工。
>
> 一个任务受阻，应继续其他不依赖该任务的工作。
>
> 不允许通过空循环、重复无意义操作或虚假汇报制造工作时长。
>
> 会话或执行环境终止时保存真实检查点，不声称仍在后台执行。

## 无人值守 ≠ 扩大目标
授权范围记录在 `WORKSPACE.run.scope`（target、game_quota、用户原话 basis）：
- 用户只要求建立 Base：达到 BASE_READY 即可交付并停止，不得未经授权自动创建大量游戏（quota = 0，工具会拒绝）。
- 用户要求完整的 Game 01：持续推进 Game 01 的策划、开发、美术、QA 和交付，直到 RELEASE_CANDIDATE 或真实阻断。
- 用户要求连续制作三款：按顺序完成约定的三款，每款中途不需要审批；做完第三款后停止。
- 用户只要求 G2 美术规划：在该阶段充分执行并自审（stage 模式，allowed_stages = [G2]），然后按阶段交接。
- 用户后来新增请求时，用 `--user-request` 记录原话，并扩展或更换范围。

未经授权不能付费、删除无关文件、推送游戏项目、公开部署或进行危险操作。

## 工作继续，边界保留
用户不承担日常项目经理的职责。普通的命名、框架选择、动作方案、数值候选、文件组织和调试手段都由执行者决定。输入有歧义时先读项目；能保守推断的就记录假设后继续，只把真正无法推断的权限、费用、权利或外部服务字段列为阻断。

开局先用现有资料整理出一个短任务队列，然后开始实际工作。禁止花半小时写长篇新规划却不检查、不编码、不测试。

## 每轮任务的五要素
选择一个能缩小重要差距的任务，写明预期产物、依赖、允许修改的范围、验收方法、失败后的替代路径。完成后保存产物和证据，再选下一项。

优先处理崩溃、卡关、错误的伤害或状态、阻断资源生产的管线问题，然后才是必要的内容和表现。多款游戏并存时，不在未授权的游戏上花时间；改 Base 之前先评估对依赖游戏的影响。

## 停止、交接与等待
- `TARGET_REACHED`：`run.scope` 定义的目标已满足。工具会核对 Base/Game 的就绪度，不满足就拒绝记录。不得自行追加无穷的新功能。
- `HANDOFF_READY`：用户只分配了阶段，阶段出口已满足；全项目是否完成另行记录。
- `EXTERNAL_BLOCKED`：授权范围内所有有价值的任务都因明确的外部条件无法继续。写明尝试过什么、为什么没有剩余可做的事、解除条件是什么。
- `RUNTIME_LIMIT`：宿主、上下文、额度或工具执行终止。只记录已知事实；原因不明就写未确认，不编造系统强制停止。
- `USER_PAUSED`：用户主动要求暂停或接手。

缺少生图能力时：把资产任务标为受阻，继续做契约、切图工具、测试、UI 布局、逻辑或其他内容，不能因为缺一项工具就停下整个工程。最后只剩正式资产时，交接未完成的资产，不宣称作品完整。

缺少法务确认或真人体验时：继续能做的工作，直到只剩这些外部事项，然后交付候选并准确说明阻断，不强行“自验通过”，也不空转十小时。

## 预算、权限和工具
WORKSPACE.permissions 可以预授权指定服务的消费上限、获准的私有仓库同步、安装范围和允许写入的目录。未配置的付费预算视为零，不认为订阅包含所有 API。允许使用已获权限且不会触发未批准收费的工具；记录实际调用，不假装生图或独立 QA 已经发生。

本地 ENVIRONMENT 记录并发测试上限（默认 2）、命令超时和缓存目录。长构建可以适当延长并观察进度，不要对仍有输出的构建盲目 kill。端口冲突就换空闲端口，只终止能确认由本任务启动且可以安全结束的进程。

不修改全局电源策略、全局 PATH 或其他工程的环境；需要机器无人值守在线时，由用户保证在线和不休眠。

## 防止空转与上下文耗尽
同一个失败默认最多用同一策略尝试 3 次；之后必须换假设、查看第一个错误、隔离最小复现或换任务。新增任务必须对应未通过的门禁或明确的玩家收益；新增文档、重复测试、提高版本号都不算完成量。

每完成一个实质任务、做风险改动前、合并前、会话余量不足时和交接前，都要保存检查点。日志按任务保存，主状态只保留必要摘要。大型原作资料按需检索，不全量塞进上下文。

## 不提供不存在的持续运行能力
本包不带定时器、自动重发消息、无限命令循环或跨软件调用器。当前 Agent 活跃期间按合同持续推进；会话结束后能否再次唤醒，取决于实际宿主能力或外部调度服务。建立这类服务需要单独的授权、预算、次数上限、锁和失败告警，不会因为一条 Skill 自动创建。
