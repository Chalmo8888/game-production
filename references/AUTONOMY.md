# 无人值守执行合同

## 工作要继续，边界也要保留
用户不承担日常项目经理职责。普通命名、框架选择、动作方案、数值候选、文件组织、调试手段由执行者决定。输入有歧义时先读项目；能保守推断的记录假设后继续，只将真正不可推断的权限、费用、权利、外部服务字段列为阻断。

开局先用现有资料形成短任务队列并开始实际工作。禁止半小时写长篇新规划却不检查、编码或测试；也不规定一律“先计划十分钟”这种与实际任务无关的时长。

## 每轮任务需要五件事
选择一个能降低重要差距的任务，写明预期产物、依赖、允许修改范围、验收方法、失败后的替代路径。完成后保存产物与证据，再选下一项。

优先解决崩溃、卡关、错误伤害/状态、阻断资源生产的管线问题，再处理必要内容与表现。可并行工作时保留依赖；修复一个像素细节不应阻止其他已具备条件的关卡工作。

## 停止、交接与等待
- `TARGET_REACHED`：PROJECT 定义的交付目标已满足。禁止自行增加无穷新功能。
- `HANDOFF_READY`：用户只分配阶段，阶段合同已满足；全项目是否完成单独记录。
- `EXTERNAL_BLOCKED`：当前授权范围内所有有价值任务都因确切外部条件无法继续。写明尝试、剩余可执行项为何没有、解除条件。
- `RUNTIME_LIMIT`：宿主/上下文/额度/工具执行终止。记录已知事实；无法知道原因就写未确认，不编造系统强制停止。
- `USER_PAUSED`：用户主动要求暂停或接手。

欠缺生图能力时：把资产任务标为受阻，继续合同、切图工具、测试、UI 布局、逻辑或其他可做内容；不能因没有一项工具就停止整个工程。若最终只剩正式资产，交接未完成资产而非宣称完整成品。

法务确认或真人体验尚缺时：继续能做的工作，到只有这些外部项时交付候选和准确阻断，不强行“自验通过”，也不空转十小时。

## 预算、权限和工具
PROJECT 可预授权指定服务的消费上限、已批准的私有仓库同步、安装范围和允许写入目录。未配置的付费预算为零，不认为订阅包含所有 API。允许使用已获得权限且不会触发未批准收费的工具；记录实际调用，不假装生图或独立 QA 已发生。

本地 ENVIRONMENT 记录并发测试上限（默认 2）、命令超时和缓存目录。长构建可适当延长并看进度，不对仍有输出的构建盲目 kill。端口冲突换空闲端口，仅终止可确认由本任务启动且安全结束的进程。

不修改全局电源策略、全局 PATH 或其他工程环境；需要无人值守机器必须由用户保证在线和不休眠。

## 防止空转与上下文耗尽
同一失败默认最多 3 次同策略尝试；之后必须换假设、查看首个错误、隔离最小复现或换任务。新增任务必须对应未通过合同或明确玩家收益；不要以新增文档、重复测试、增加版本号作为完成量。

每完成一个实质任务、风险改动前、合并前、会话余量不足或交接前保存检查点。日志按任务保存，主状态只保留必要摘要。大型原作资料按需检索，不全量塞入上下文。

## 不提供不存在的持续运行能力
本包不带定时器、自动重发消息、无限命令循环或跨软件调用器。当前 Agent 活跃期间按合同持续推进；会话结束后的再次唤醒依赖实际宿主能力或外部调度服务。建立这类服务需单独授权、预算、次数上限、锁和失败告警，不因一条 Skill 自动创建。
