# 跨设备、跨 Agent 接续

## 推荐默认：仓库随项目走，单写入者接力
每个游戏仓库包含一份固定版本 `.agents/skills/game-production/` 和 `.production/` 项目状态。套件主副本单独管理，升级按版本应用；不要让某台机器的全局 Skill 无提示覆盖项目规则。

代码、可共享资源、合同、任务和精简证据随项目同步。凭据、研究原件、缓存、node_modules、venv、编译 SDK 等不随便同步。大型授权资产可独立传输，但要有路径/哈希清单；“Git 已同步”不能证明资产都在。

## 设备 A 交出
完成当前安全操作，停止继续写入。保存必要改动和本地提交（不要把无关未提交文件一起纳入），更新 STATE/HANDOFF：最后版本、脏工作树、未跟踪文件、下一任务、资产和证据清单、已启动本机服务。默认不 push；明确预授权某个私有仓库/分支后才能自动同步。

无法联网可交付经审查的项目快照加清单；Git bundle 需要另含未提交、未跟踪、大资产的处理说明。不能只交 dist 或只交 Skill。

## 设备 B 接手
核对目标仓库和快照、本地已有改动、缺失资产与引用。创建/刷新 `.production/local/ENVIRONMENT.json`，探测 OS、依赖、终端、浏览器与生成工具。按项目锁文件装依赖，执行最小构建和冒烟测试。使用 HEAD 和证据更新任务选择，不根据旧聊天重新开始。

Windows 若确有 E 盘，缓存和构建下载优先放该盘允许目录；Mac/Linux 仅用实际目录。公共文件用相对路径，不把 E 盘路径写死进源码与合同。不要改全局 PATH 来修项目路径。前一台机器的 localhost URL 无法证明当前机器服务存在，需重新启动并记录端口。

## 并行不是默认
同一工作树两个写入者会制造冲突。确需并行：分支/独立工作树，任务 ID 与文件归属，资产合同版本固定，指定集成者；合并后重新 QA。Git 工作树用法看官方文档，不 force 覆盖对方改动。

`.production/STATE.json` 的 active_session 是合作提示，不是跨设备分布式锁。离线双端无法靠一个 JSON 自动互斥；未确认写入归属时先只读审查，不擅自同时写主分支。

## 工具和权限可换，工作目标不换
本机可浏览/不可生图，下一台可生图/没有浏览器，均按能力选择未阻断任务。切换软件不改变目标、验证状态或授权；也不自动授予新设备收费 API/远程发布权限。

若用户只希望“这台做 S2/S3、下台做 S4/S5”，用 stage 模式；其余使用 auto。单 Agent 不需要伪造交接给自己；保留相同标准即可。
