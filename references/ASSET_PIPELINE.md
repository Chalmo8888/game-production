# 资产生产、替换与集成合同（不绑定生成工具）

## 先保留现有管线
检查已有加载器、图集、骨骼/逐帧动画、字体与音频映射。已有工具经来源审查和功能验证可用时继续用；不要为切换 Agent 重建。恢复资源加载合同不代表恢复作者原始美术制作源工程。

资源路径是制作层，游戏引用使用稳定语义 ID；格式由项目决定，不硬绑 unit.json、Spine、Phaser、WASM 或某个生图 API。

## 合同字段
每项资产记录：ID、用途、状态、必需动作、朝向、逻辑单位尺寸、输出尺寸范围、缩放、pivot/脚点、发射/命中/挂载点、图层、播放方式、循环/非循环、表现事件、音频、导入命令、测试场景、来源与预算。合同有版本，修改会列出影响的全部消费者。

逻辑移动、冷却、伤害和碰撞以显式规则为权威。图像大小、透明裁切、帧排列不应暗中改规则。继承实现确有这类耦合时建立适配与兼容测试，不能直接“解耦”却破坏现有手感。

## 生产顺序
选择有代表性的单位/角色及场景，先做一次需求→生成/制作→加工→导入→运行时检查。通过后再扩展同风格同合同资产；不要一口气生成数百张、最后才发现图集切不出来。

生成工具由环境能力决定。仅使用真实可调用且预算授权的工具；批次可控、失败有重试上限。没有生图工具时完成合同/加工器/其他任务并交接，不随便抓商业游戏资源，不将程序占位称正式手绘资产。

可用逐帧、骨骼、纸娃娃或合理程序动画；不为了“必须逐帧”否定有效方案。验收看实际动作、脚点、挂点、连贯性和战斗同步，不看文件数量。

## 运行时验证
- 源图是生产原料，runtime atlas/clip、注册表和实机序列才是集成证据。
- 检查透明边界、缩放、朝向、攻击瞬间发射位置、受击/死亡、场景碰撞与图层。
- UI 检查不同窗口，字幕不持续挡战斗，像素字体/中文覆盖范围明确。
- 正式资源清单扫描实际包；缺失回退在开发模式显式提示，候选的必需资产不能默默回落到占位。
- 声音要验证播放、音量总线、并发、循环/结束和用户手势恢复；文件存在不等于已试听通过。
- 替换前后跑相关机制回归；仅美术改动不应改变伤害、移动或冷却。

## 交接
合同、已接受资产、被拒原因、剩余清单、工具调用记录和输出规范一起交接；不要求接手者知道前任使用哪个软件。记录未完成音乐和字体，不自动将它们当不需要。
