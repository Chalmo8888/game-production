# 阶段合同与非线性推进

执行者统一称“当前 Agent”。可自动串行切换研究者、实施者、资产制作者、审查者职责；不要求特定产品或多个账号。

## S0 接管、范围、来源与路线
输入：用户目标、当前目录、已有源码/游戏包/公开参考链接、现有测试和文档。
动作：核实版本和已有成果，分离研究原件、获准复用内容、发行项目。以依赖关系决定保留、适配、隔离和替换，不以语言或 Agent 喜好重做引擎。
产物：PROJECT、任务池、来源清单、能力探测、最小路线决策。
出口：目标和必要机制清楚；已选择可执行且来源边界合理的路线。不以开源标识代替来源判断。
对于已有游戏项目：直接审查现有游戏、资源工具及未通过项；不得重新逆向或新建不必要的空引擎。

## S1 机制、来源与资源调查（有需要时）
优先使用用户已有文件与有效研究，再调查外部公开资料。读取到的代码是实际原始源码、反编译恢复物、格式化 bundle 还是独立实现，要准确命名。
产物：机制对照矩阵，含版本/哈希、定位、规则、参数单位、状态/调用关系、研究可达范围与缺口。资源侧记录实际存在的加载/图集/动画合同；恢复运行时资源组织不等于恢复作者的 Photoshop/Spine 原工程。
研究要服务已锁定目标。不为“完全逆向”无限分析与游戏无关的联机逻辑；不能只列函数名就做一个自行编造规则的替代品。
出口：交付所需机制足以支撑实现；未知项不影响核心目标或有获准的替代计划。原作动态无法运行时保留 STATIC_ONLY，不猜测补齐证据。

## S2 实现、改良与完整内容
以合法成熟实现为优先，不擅自翻译所有语言、换引擎或新建第 N 个工程。确需替换时保存可用工具、资产接口、黑盒基准和验收目标；逐项记录能力是否保留、改良、替代或尚缺。
先建代表性闭环验证体系，再自主扩展到 PROJECT 的真实内容目标。一个教学关卡不是默认终点；也不固定所有项目必须 20 关/13 单位/某个引擎。
涉及已有 Creator Base 时遵守其核心修改边界，不为了新增游戏内容修改受保护核心。
出口：范围内系统和内容真正存在，普通输入和失败恢复可验证；未覆盖机制明确，不用“能启动”冒充完成。

## S3 资源契约与小批量接入
可与 S2 早期并行。读取资产管线手册，先建立一个角色/单位和一个场景的最小代表资产，完成导入、替换、实机动画和逻辑一致性测试后再批量。
出口：契约版本确定，资产生产者不必读原研究代码即可工作，缺失/错误输入可报错，未覆盖资源显示有标记的回退。
若用户只要逻辑与管线，这可以是授权交接出口；不是完整发行出口。

## S4 正式资产生产与集成
依据现有契约完成角色、敌人、地形、UI、音频、字体等本项目实际所需项。已有达标资产直接保留，不为统一新模型而重生所有图。
将“需求→源图→加工→导入→运行时验证→接受/拒绝”记录到资产清单。跨批次一致性与动作状态覆盖优先于一次生成巨大图集。
出口：所有在范围内的玩家可见资源有正式版本且通过运行时检查；没有因静默回退而漏资产。未取得工具或预算时保持阻断，不用大量占位骗过门禁。

## S5 综合测试与审查（持续运行）
实施任务结束即做局部 QA；阶段验收审查整个目标构建。审查者需要读实物和复现，不照抄开发报告。可同 Agent 自审；独立上下文的 QA 需真实存在并标记级别。
流程失败、视觉异常、不可用单位、存档错误、性能退化分别回到相关任务；不是每次返工从 S0 开始。
出口：适用门禁真实 PASS；不能自动判断项明确保留，候选标记不得抹掉它们。

## S6 构建、交接与上线边界
从干净可重现输入构建；验证入口、依赖、资源路径、宿主协议、存档作用域、测试接口、凭据/私密路径泄漏和依赖附带义务。输出包和证据带 SHA-256、提交或工作树快照、环境信息。
读取真实平台 SDK/发布契约，未知就写待适配，不猜测字段、不覆盖现有 game ID、slug、release 身份。
本地候选包、可交给下一 Agent 的阶段包、授权公开发布分别记录。公开发布必须另有明确授权；权限不是 GATES 自动生成的。

## 阶段跳过和回退
有效证据覆盖且当前版本一致可复用阶段。用户明确不需要的能力可 N/A，工具缺失不能 N/A。已通过阶段如依赖变更导致证据过期就回退受影响项。审查中发现一个缺陷，不因此将不相关的已验证机制全部重做。
